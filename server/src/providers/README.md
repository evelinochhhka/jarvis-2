# Адаптер языковой модели

Серверная логика не должна зависеть от SDK одного поставщика.

Планируемый интерфейс адаптера:

- вход: история сообщений, системные правила, параметры генерации;
- выход: текст ответа и метаданные использования, если поставщик их возвращает;
- ошибки: единые внутренние коды для тайм-аута, ограничения частоты, недоступности и неверной конфигурации;
- потоковая выдача может быть добавлена как отдельная возможность адаптера.

Требования безопасности:

1. Ключ хранится только в серверном secret storage / переменной окружения.
2. Ключ не включается в клиентские сборки, ответы API, трассировки или Git.
3. Не передавать поставщику больше истории, чем нужно для конкретного запроса.
4. Установить лимит длины истории и размера ответа.
5. Ошибки поставщика очищать от секретов перед журналированием.

Точный поставщик и модель не выбраны. Реализация SDK начнётся после согласования платформы, способа хранения секрета и бюджета. Не использовать фиктивные ключи или тестовые ответы, выдаваемые за реальную работу ИИ.
