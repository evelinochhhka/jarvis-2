# Серверная часть JARVIS 2

## Что реализовано

Минимальный HTTP API на встроенном модуле Node.js, без сторонних серверных зависимостей:

- `GET /api/v1/health` — проверка API и наличия конфигурации ИИ без раскрытия секретов.
- `POST /api/v1/chat` — проверка запроса и передача сообщения через OpenAI-compatible адаптер.
- Провайдер по умолчанию: OpenRouter, модель-кандидат `nvidia/nemotron-3-ultra-550b-a55b:free`. Это выбранный бесплатный маршрут для прототипа, а не гарантия постоянной доступности или объективного лидерства модели.
- Резервный вариант можно настроить через Groq и совместимую модель, изменив переменные окружения.
- Русско-украинская системная инструкция, обращение к пользователю на «вы».
- Ограничение размера тела запроса, тайм-аут, проверка языка и безопасные сообщения об ошибках.
- Базовый фиксированный per-IP rate limit для endpoint чата. Счётчики хранятся в памяти одного процесса.
- Ограничение CORS при заданном `APP_ORIGIN`.
- Необязательная Bearer-аутентификация чата через `API_ACCESS_TOKEN`; сравнение токена выполняется с constant-time функцией для одинаковой длины.
- Ключ провайдера используется только на сервере.

## Локальный запуск

Требуется Node.js 20 или новее.

1. Скопируйте `.env.example` в локальный файл окружения и задайте значения в среде запуска. Сам сервер намеренно не загружает dotenv и не читает секреты из файлов.
2. Для защищённого сервера сгенерируйте случайный токен командой `npm run generate:server-token`, затем сохраните его в секретах окружения как `API_ACCESS_TOKEN`. Команда генерирует токен длиной 48 случайных байт и ничего не записывает в репозиторий.
3. Установите переменные окружения `AI_API_KEY`, `AI_MODEL`, `AI_BASE_URL`, `APP_ORIGIN`, `API_ACCESS_TOKEN`, `HOST` и `PORT`.
4. Запустите `npm run start:server`.
5. Проверьте `GET http://127.0.0.1:8787/api/v1/health`.

Если ключ не задан, health вернёт `aiConfigured: false`, а чат ответит `503 AI_NOT_CONFIGURED`. Это намеренное поведение, а не имитация работающего ИИ.

## Текущие ограничения и безопасность

Это технический прототип, а не готовый публичный сервер:

- нет регистрации, управления пользователями и ролями; при заданном `API_ACCESS_TOKEN` есть общий статический Bearer-токен для одного доверенного пользователя;
- нет базы данных, облачного сохранения истории диалогов и памяти;
- нет инструментов управления списками, устройствами или приложениями на сервере;
- rate limit работает только в памяти одного процесса и не заменяет защиту на уровне шлюза или пользователя;
- нет потоковой передачи ответа;
- нет развёртывания и готовой HTTPS-конфигурации;
- CORS не является аутентификацией и не защищает API от прямых запросов. При пустом `API_ACCESS_TOKEN` чат остаётся без токенной защиты. Для публичного развёртывания задайте длинный случайный токен, HTTPS и дополнительную защиту на reverse proxy.

Не публикуйте этот API в интернете до полноценной пользовательской аутентификации, HTTPS, устойчивого ограничения запросов и защиты персональных данных. Общий Bearer-токен снижает риск случайного доступа, но не является полной системой управления пользователями. Для внешнего провайдера отдельно проверьте возрастные условия, политику обработки данных и тариф вместе с ответственным взрослым. Не передавайте ключи в переписку или репозиторий.
