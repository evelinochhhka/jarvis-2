# Серверная часть JARVIS 2

## Реализовано

Минимальный HTTP API на Node.js:
- `GET /api/v1/health` — состояние API и флаги настройки ИИ/Web Push без раскрытия секретов.
- `POST /api/v1/chat` — проверка запроса и передача сообщения через OpenAI-compatible адаптер.
- OpenRouter с моделью-кандидатом `nvidia/nemotron-3-ultra-550b-a55b:free`; доступность бесплатной модели не гарантируется.
- Русско-украинская системная инструкция и обращение на «вы».
- Ограничение размера тела, тайм-аут, проверка языка, безопасные ошибки, CORS и per-IP rate limit в памяти процесса.
- Необязательная Bearer-аутентификация чата и обязательная Bearer-аутентификация для изменения push-подписок.
- Web Push через VAPID: публичный ключ, регистрация и удаление подписок, хранение в JSON-файле с атомарной записью, контрольная отправка при подключении и удаление endpoint при ответах 404/410.
- До 20 зарегистрированных устройств на один общий токен.
- Ключ провайдера и VAPID private key остаются в переменных окружения сервера.

## Настройка

Требуется Node.js 20 или новее.

1. Установите зависимости: `npm install`.
2. Скопируйте `.env.example` в собственную конфигурацию окружения. Сам сервер не читает секреты из файлов.
3. Сгенерируйте токен: `npm run generate:server-token`. Сохраните его как `API_ACCESS_TOKEN` в секретах сервера.
4. Сгенерируйте VAPID-пару: `npm run generate:vapid-keys`. Скопируйте значения в серверные секреты `VAPID_PUBLIC_KEY` и `VAPID_PRIVATE_KEY`, а `VAPID_SUBJECT` замените на действующий контакт.
5. Задайте `AI_API_KEY`, `AI_MODEL`, `AI_BASE_URL`, `APP_ORIGIN`, `HOST` и `PORT`.
6. Запустите `npm run start:server`.

Push-подписки сохраняются в `server/data/push-subscriptions.json`. Каталог исключён из Git. Для надёжной эксплуатации используйте постоянный диск и резервное копирование; при нескольких экземплярах сервера понадобится общее хранилище и распределённая блокировка.

## Ограничения и безопасность

Это не готовая публичная инфраструктура:
- нет отдельных аккаунтов, ролей, OAuth или управления устройствами; общий токен фактически даёт доступ владельцу секрета;
- нет базы данных, облачной истории, памяти и синхронизации списков;
- push-подписки сохраняются на сервере, но полноценный планировщик персональных напоминаний ещё не реализован;
- rate limit хранится в памяти одного процесса;
- нет потоковой передачи ответа и готовой HTTPS-конфигурации;
- при пустом `API_ACCESS_TOKEN` чат не защищён токеном, а изменение push-подписок намеренно отключено;
- CORS не является аутентификацией.

Не публикуйте сервер до HTTPS, проверки reverse proxy, защиты секретов, резервного копирования и проверки приватности. Не добавляйте ключи в Git или переписку. Условия внешнего AI-провайдера и обработку данных следует проверить вместе с ответственным взрослым.
