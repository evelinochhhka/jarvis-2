# Серверная часть JARVIS 2

## Что реализовано

Минимальный HTTP API на встроенном модуле Node.js, без сторонних серверных зависимостей:

- `GET /api/v1/health` — проверка API и наличия конфигурации ИИ без раскрытия секретов.
- `POST /api/v1/chat` — проверка запроса и передача сообщения через OpenAI-compatible адаптер.
- Адаптер по умолчанию настроен на Groq и модель `openai/gpt-oss-120b`, но провайдера, URL и модель можно заменить конфигурацией.
- Русско-украинская системная инструкция, обращение к пользователю на «вы».
- Ограничение размера тела запроса, тайм-аут, проверка языка и безопасные сообщения об ошибках.
- Ключ провайдера используется только на сервере.

## Локальный запуск

Требуется Node.js 20 или новее.

1. Скопируйте `.env.example` в локальный файл окружения и задайте значения в среде запуска. Сам сервер намеренно не загружает dotenv и не читает секреты из файлов.
2. Установите переменные окружения `AI_API_KEY`, `AI_MODEL`, `AI_BASE_URL`, `APP_ORIGIN`, `HOST` и `PORT`.
3. Запустите `npm run start:server`.
4. Проверьте `GET http://127.0.0.1:8787/api/v1/health`.

Если ключ не задан, health вернёт `aiConfigured: false`, а чат ответит `503 AI_NOT_CONFIGURED`. Это намеренное поведение, а не имитация работающего ИИ.

## Текущие ограничения

Это технический прототип, а не готовый публичный сервер:

- нет регистрации, аутентификации и базы данных;
- нет сохранения истории диалогов и памяти;
- нет инструментов управления списками, устройствами или приложениями;
- нет ограничения частоты запросов и защиты от злоупотребления на уровне пользователя;
- нет развёртывания и HTTPS-конфигурации;
- нет потоковой передачи ответа.

Не публикуйте этот API в интернете до реализации аутентификации, rate limiting, HTTPS и защиты персональных данных. Для внешнего провайдера отдельно проверьте возрастные условия, политику обработки данных и тариф. Не передавайте ключи в переписку или репозиторий.
