# Коммуникации и звонки: требования и ограничения iOS

Дата фиксации: 2026-11-22

## Цель пользователя

JARVIS 2 должен помогать управлять коммуникациями с iPhone/iPad:
- получать и озвучивать уведомления;
- показывать доступное содержимое уведомлений от Telegram, Instagram и TikTok;
- помогать читать входящие сообщения и готовить ответы;
- по явному разрешению пользователя отправлять ответы там, где платформа официально предоставляет такую возможность;
- помогать с телефонными звонками: принять вызов, включить громкую связь и завершить вызов.

Это целевые требования. Нельзя показывать их как реализованные, пока они не проверены на реальном устройстве и в рамках публичных API.

## Ограничения iOS

iOS не предоставляет обычному стороннему приложению универсальный доступ ко всем уведомлениям других приложений и общий API для управления чужими звонками.

### Уведомления

- Приложение JARVIS может получать собственные уведомления и управлять ими после разрешения пользователя.
- Нельзя обещать, что PWA или обычное приложение сможет читать содержимое всех уведомлений Telegram, Instagram и TikTok из системного Notification Center.
- У Apple есть Accessory Notifications для пересылки уведомлений на специально разработанный аксессуар. По документации Apple это framework для iPhone, а пользовательские установки ограничены устройствами в ЕС с Apple Account региона ЕС. Это не универсальный API для приложения JARVIS и не подходящий основной путь для пользователя в Украине.
- В качестве поддерживаемого варианта можно исследовать системные функции Siri для объявления уведомлений и доступные пользователю средства автоматизации, не обещая их полного контроля со стороны JARVIS.

### Telegram

- Telegram Bot API не предоставляет боту доступ ко всем личным сообщениям пользователя.
- Telegram Business поддерживает подключение бизнес-бота к аккаунту с правами на выбранные чаты и разрешённые действия. Это отдельный сценарий, зависящий от типа аккаунта, настроек и согласия владельца.
- Не использовать неофициальный сбор сообщений, хранение пароля пользователя или обход ограничений Telegram.

Официальная документация:
- https://core.telegram.org/bots/features
- https://telegram.org/faq

### Instagram

- Официальный Instagram Messaging API ограничен профессиональными аккаунтами, связанными с Facebook Page, и требует соответствующих разрешений и проверки приложения.
- Это не даёт JARVIS универсального доступа к личным перепискам обычного Instagram-аккаунта.
- Не использовать парсинг интерфейса, перехват сессии или передачу пароля.

Официальная документация:
- https://developers.facebook.com/docs/graph-api/reference/message

### TikTok

- Не считать чтение личных сообщений или системного центра уведомлений TikTok доступным через общий публичный API.
- Возможности TikTok необходимо перепроверять по официальной документации при реализации. Не использовать неофициальные API и обходы.

## Звонки на iPhone/iPad

### Обычные телефонные вызовы и вызовы сторонних приложений

- CallKit предназначен для интеграции звонков, которые предоставляет само приложение или его VoIP-служба.
- CallKit не является универсальным разрешением отвечать на обычные сотовые вызовы Phone, завершать их или переключать их на громкую связь из другого приложения.
- Возможность выбрать стороннее приложение приложением вызовов по умолчанию в iOS/iPadOS 18.2+ относится к обработке исходящих вызовов через это приложение. Она не означает, что JARVIS получает управление входящими сотовыми вызовами.
- Нельзя обещать программное включение громкой связи или завершение обычного телефонного вызова через публичный API стороннего приложения.

Официальная документация:
- https://developer.apple.com/documentation/callkit
- https://developer.apple.com/documentation/callkit/preparing-your-app-to-be-the-default-calling-app
- https://developer.apple.com/documentation/pushkit/responding-to-voip-notifications-from-pushkit

## Практический план реализации

1. Сделать JARVIS центром собственных уведомлений, задач и напоминаний.
2. Изучить поддерживаемые Siri/iOS способы объявления уведомлений и голосового взаимодействия; документировать точные ограничения.
3. Для Telegram отдельно оценить Telegram Business Bot только если пользователь решит использовать подходящий бизнес-сценарий. Не считать его заменой доступа ко всем личным чатам.
4. Для Instagram рассматривать официальный Messaging API только для профессионального аккаунта и только после выполнения требований Meta.
5. Для TikTok оставить интеграцию сообщений и уведомлений как неподтверждённую, пока официальный API не предоставляет нужные права.
6. Для звонков использовать CallKit только для собственного VoIP-модуля JARVIS, если такой модуль когда-либо будет нужен.
7. Для обычных сотовых и сторонних звонков честно показывать, что системные ограничения не дают JARVIS напрямую принять вызов, включить громкую связь или завершить его.
8. Не запрашивать у пользователя пароли от соцсетей и не хранить токены в клиенте. Любые разрешённые интеграции должны использовать официальную OAuth-авторизацию и защищённое серверное хранение токенов.

## Проверка перед выпуском

Для каждой платформы отдельно зафиксировать:
- какой тип аккаунта поддерживается;
- какие данные реально доступны;
- какие разрешения запрашиваются;
- можно ли читать сообщения, отвечать, отмечать прочитанным;
- можно ли получать события в фоне;
- что работает на iPhone и что на iPad;
- какие функции недоступны в регионе пользователя.

До прохождения этих проверок в интерфейсе использовать формулировки «не поддерживается» или «требует интеграции», а не обещать автоматический контроль.


## Web Push для установленной PWA

Для текущей веб-архитектуры наиболее реалистичный первый шаг — Web Push для собственных уведомлений JARVIS. Apple поддерживает Web Push для веб-приложений, добавленных на экран «Домой», начиная с iOS/iPadOS 16.4. Для доставки нужны разрешение пользователя, Push API, service worker, подписка устройства и сервер, который отправляет зашифрованные push-сообщения через VAPID. Это не даёт доступ к уведомлениям других приложений.

Официальная инструкция Apple: https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers

### Подготовлено в клиенте

- экран «Связь и уведомления»;
- проверка поддержки Push API и разрешения браузера;
- запрос разрешения только после нажатия пользователя;
- создание/удаление push-подписки через серверные API;
- обработка push-события и нажатия на уведомление в service worker.

### Что ещё требуется на сервере

- создать VAPID public/private key pair; приватный ключ хранить только в серверных переменных окружения;
- реализовать `GET /api/v1/push/public-key`;
- реализовать авторизованный `POST /api/v1/push/subscriptions` и `DELETE /api/v1/push/subscriptions`;
- хранить подписки с привязкой к аккаунту, удалять недействительные endpoints и отправлять только уведомления, разрешённые пользователем;
- реализовать планировщик напоминаний с часовым поясом, повторами, защитой от дублей и обработкой смены времени;
- добавить аутентификацию и защиту от CSRF/подмены подписок до включения персональных уведомлений.

Пока серверных endpoints и аутентификации нет, подписка не считается активной и доставка не обещается. В iOS/iPadOS веб-push следует проверять при запуске установленной PWA с экрана «Домой», а не только во вкладке браузера.

## Нативный модуль звонков

Если позднее будет создано нативное приложение iOS, отдельный VoIP-сервис можно интегрировать через PushKit и CallKit. Это собственная телефонная служба JARVIS, а не управление звонками Telegram, Instagram, TikTok или обычной сотовой связью. PushKit VoIP push разрешено использовать только для реальных приглашений на VoIP-звонки; Apple требует быстро сообщать о таком вызове в CallKit.

Официальные источники:
- https://developer.apple.com/documentation/PushKit/responding-to-voip-notifications-from-pushkit
- https://developer.apple.com/documentation/callkit/making-and-receiving-voip-calls
