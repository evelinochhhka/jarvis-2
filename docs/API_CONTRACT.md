# JARVIS 2 API contract

Версия контракта: 0.1. Статус: проектирование, сервер ещё не развёрнут.

Все маршруты ниже предполагают префикс `/api/v1`. Контракт не привязан к конкретному хостингу или поставщику языковой модели.

## Общие правила

- Формат запросов и ответов: JSON, UTF-8.
- Ошибки имеют единый формат: `{ "error": { "code": "...", "message": "..." } }`.
- Клиент не получает ключи поставщиков моделей и не вызывает их API напрямую.
- Все пользовательские данные принадлежат отдельному пользователю и не должны смешиваться между аккаунтами.
- До реализации аутентификации нельзя публиковать маршруты, возвращающие или изменяющие личные данные.
- Запросы к модели должны иметь ограничение размера, времени ожидания и частоты.
- Ответ модели рассматривается как недоверенный текст, а не как исполняемая команда.

## Маршруты

### GET /health

Проверка доступности сервера. Не раскрывает секреты, конфигурацию окружения или внутренние адреса.

Ответ 200:
```json
{ "status": "ok", "apiVersion": "v1" }
```

### POST /chat

Отправка сообщения ассистенту.

Запрос:
```json
{
  "conversationId": null,
  "message": "Текст сообщения",
  "clientRequestId": "uuid"
}
```

Ответ:
```json
{
  "conversationId": "uuid",
  "message": {
    "id": "uuid",
    "role": "assistant",
    "content": "Ответ ассистента",
    "createdAt": "ISO-8601"
  }
}
```

До настройки модели сервер возвращает `503 AI_NOT_CONFIGURED`, а не имитирует ответ.

### GET /conversations

Список диалогов текущего пользователя с пагинацией.

### GET /conversations/{id}

Сообщения выбранного диалога текущего пользователя.

### DELETE /conversations/{id}

Удаление диалога и связанных сообщений текущего пользователя.

### GET /lists/{type}

Получение списка. Допустимые типы: `tasks`, `watchlist`, `wishlist`.

### POST /lists/{type}

Добавление элемента. Поля элемента будут уточнены при реализации модели данных.

### PATCH /lists/{type}/{id}

Изменение элемента.

### DELETE /lists/{type}/{id}

Удаление элемента.

### GET /reminders

Получение напоминаний текущего пользователя.

### POST /reminders

Создание разового или повторяющегося напоминания. Дата и время передаются в ISO-8601 с часовым поясом.

### PATCH /reminders/{id}

Изменение напоминания, включая включение и отключение.

### DELETE /reminders/{id}

Удаление напоминания.

## Планируемая модель данных

- `users`: идентификатор внешнего провайдера аутентификации и настройки профиля.
- `conversations`: владелец, заголовок, временные метки.
- `messages`: диалог, роль, текст, временная метка.
- `list_items`: владелец, тип списка, название, заметка, статус, временные метки.
- `reminders`: владелец, текст, время, часовой пояс, правило повторения, статус.
- `memory_items`: владелец, факт, источник, дата создания, признак подтверждения.

Пользовательская память должна быть редактируемой и удаляемой. Не сохранять чувствительные сведения без отдельной необходимости и явного согласия.

## Статус

Контракт описывает будущую интеграцию. Ни один из этих маршрутов пока не опубликован и не должен считаться работающим.
