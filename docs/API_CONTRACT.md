# JARVIS 2 API contract

Версия контракта: 0.3. Статус: минимальный серверный прототип реализован; публичное развёртывание и пользовательские данные пока не поддерживаются.

Все маршруты используют префикс `/api/v1`. Контракт не привязан к конкретному поставщику языковой модели.

## Общие правила

- Формат запросов и ответов: JSON, UTF-8.
- Ошибки имеют единый формат: `{ "error": { "code": "...", "message": "..." } }`.
- Клиент не получает ключи поставщиков моделей и не вызывает их API напрямую.
- До реализации аутентификации нельзя публиковать маршруты, возвращающие или изменяющие личные данные.
- Запросы к модели ограничиваются размером и временем ожидания. Пользовательский rate limiting ещё не реализован.
- Ответ модели рассматривается как недоверенный текст, а не как исполняемая команда.
- Основные языки общения: русский (`ru`) и украинский (`uk`).
- `language` принимает `auto`, `ru` или `uk`; `preferredLanguage` принимает `ru` или `uk`.
- Системная инструкция просит модель отвечать на языке сообщения и обращаться к пользователю на «вы». Качество обоих языков ещё требует живых тестов.

## Реализованные маршруты

### GET /health

Проверка доступности API и наличия конфигурации ИИ. Не раскрывает ключи и другие секреты.

Ответ 200:
```json
{ "status": "ok", "apiVersion": "v1", "aiConfigured": false }
```

`aiConfigured` означает, что необходимые значения конфигурации заданы, а не то, что провайдер доступен прямо сейчас.

### POST /chat

Отправка одного сообщения провайдеру через OpenAI-compatible адаптер.

Запрос:
```json
{
  "conversationId": null,
  "message": "Текст сообщения",
  "clientRequestId": "uuid",
  "language": "auto",
  "preferredLanguage": "ru"
}
```

`message` обязателен, максимум 6000 символов. Тело запроса ограничено настройкой `MAX_REQUEST_BYTES`. Поля `language` и `preferredLanguage` проверяются, если переданы.

Ответ 200:
```json
{
  "conversationId": "uuid",
  "language": "ru",
  "message": {
    "id": "uuid",
    "role": "assistant",
    "content": "Ответ ассистента",
    "createdAt": "ISO-8601"
  }
}
```

При отсутствии ключа сервер возвращает `503 AI_NOT_CONFIGURED`. При лимите провайдера возвращается `429 AI_RATE_LIMITED`; при тайм-ауте `504 AI_TIMEOUT`. Ответы провайдера не сохраняются в истории.

## Планируемые маршруты

Следующие маршруты не реализованы и не должны считаться рабочими:

- `GET /conversations` — список диалогов пользователя.
- `GET /conversations/{id}` — сообщения выбранного диалога.
- `DELETE /conversations/{id}` — удаление диалога и связанных сообщений.
- `GET /lists/{type}`, `POST /lists/{type}`, `PATCH /lists/{type}/{id}`, `DELETE /lists/{type}/{id}` — синхронизируемые списки.
- `GET /reminders`, `POST /reminders`, `PATCH /reminders/{id}`, `DELETE /reminders/{id}` — синхронизируемые напоминания.
- API управления подтверждённой пользовательской памятью.

## Планируемая модель данных

- `users`: идентификатор пользователя и настройки профиля, включая язык интерфейса и предпочтительный язык общения.
- `conversations`: владелец, заголовок, временные метки.
- `messages`: диалог, роль, текст, язык сообщения, временная метка.
- `list_items`: владелец, тип списка, название, заметка, статус, временные метки.
- `reminders`: владелец, текст, время, часовой пояс, правило повторения, статус.
- `memory_items`: владелец, факт, источник, дата создания, признак подтверждения.

Пользовательская память должна быть редактируемой и удаляемой. Не сохранять чувствительные сведения без отдельной необходимости и явного согласия.

## Безопасность и развёртывание

Текущий серверный прототип не имеет аутентификации, базы данных, пользовательского rate limiting и HTTPS-конфигурации. Не публиковать его в интернете и не использовать для реальных личных данных до реализации этих механизмов. Ключ провайдера хранится только в серверном окружении. CORS можно ограничить через `APP_ORIGIN`.
