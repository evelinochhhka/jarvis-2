# JARVIS 2: архитектура проекта

## Цель

JARVIS 2 — персональный двуязычный ассистент с текстовым и голосовым интерфейсом, памятью, историей диалогов, пользовательскими списками и адаптацией под iPhone и iPad. Основные языки: русский и украинский.

Название, визуальный стиль и отдельные компоненты должны оставаться заменяемыми. Не считать текущий дизайн или рабочее название окончательными.

## Языковое поведение

1. Ассистент должен полноценно понимать русский и украинский языки, включая естественную разговорную речь, длинные фразы и контекстные команды.
2. По умолчанию JARVIS определяет язык текущего сообщения и отвечает на том же языке. Если пользователь явно выбрал язык интерфейса или общения в настройках, этот выбор имеет приоритет, пока пользователь не попросит переключиться.
3. Пользователь может свободно переключаться между русским и украинским в одном диалоге. Смешанная речь не должна приводить к потере смысла.
4. Интерфейс, системные сообщения, даты, форматы и голосовые ответы должны поддерживать оба языка.
5. Настройка языка интерфейса отделена от языка общения: пользователь может, например, оставить интерфейс на украинском, а общаться по-русски.
6. Распознавание речи и синтез речи должны иметь отдельные настройки языка и голоса. Для русского голоса из первой версии, обозначенного как `ru m5`, необходимо найти точный движок и модель. Не заменять его Piper или другим голосом без проверки и согласования. Для украинского подобрать отдельный качественный голос после проверки доступных движков.
7. Не считать поддержку языка реализованной только потому, что переведены подписи интерфейса. Требуются проверка понимания, генерации ответов, распознавания речи и озвучивания на обоих языках.

## Коммуникации и управление звонками

Требования и платформенные ограничения интеграций Telegram, Instagram, TikTok, системных уведомлений и телефонных вызовов описаны в `docs/COMMUNICATIONS_AND_CALLS.md`. Не обещать универсальный доступ к чужим уведомлениям или управление обычными сотовыми вызовами: iOS ограничивает такие возможности. Использовать только официальные API и разрешённые системные механизмы.

## Голоса Apple на iPad и iPhone

Для озвучивания предусмотреть несколько сменных вариантов:

- В веб-версии/PWA проверить поддержку Web Speech API `speechSynthesis` в Safari и использовать только реально доступные системные голоса. Наличие конкретного голоса и качество русского/украинского произношения проверять на устройстве; браузер может предоставлять не все голоса и не все настройки iPadOS.
- Для будущей нативной версии iOS/iPadOS предусмотреть адаптер на базе Apple `AVSpeechSynthesizer`, который использует установленные системные голоса устройства.
- В настройках дать отдельно выбрать голос для русского и украинского языков, а также вариант автоматического выбора по языку ответа.
- Системные голоса Apple являются дополнительным вариантом, а не автоматической заменой исходного голоса `ru m5`. Сначала установить точный движок и модель `ru m5`; не удалять и не заменять этот вариант без согласования.
- Не обещать доступность конкретного голоса, пока он не проверен на целевом устройстве.

## Принципы

1. Сначала надёжная основа, затем функции и визуальная полировка.
2. Интерфейс не содержит секретов и ключей внешних API.
3. Все внешние запросы к моделям выполняются через серверный слой.
4. Хранилище отделено от интерфейса и бизнес-логики.
5. Голосовой движок является сменным адаптером.
6. Все пользовательские данные и настройки должны быть переносимыми и иметь понятный механизм резервного копирования.
7. Приложение должно корректно работать на iPhone и iPad, включая сенсорное управление.
8. Не добавлять функции, которые заявлены в интерфейсе, пока они действительно не работают.

## Целевая структура

```
/
  index.html                 # точка входа интерфейса
  manifest.json              # PWA metadata
  sw.js                      # service worker, только после настройки кэша
  src/
    app/                     # запуск приложения и маршрутизация экранов
    components/              # переиспользуемые UI-компоненты
    features/
      chat/                  # диалог и история
      lists/                 # задачи, просмотр, хотелки
      reminders/             # напоминания
      voice/                 # запись, распознавание, воспроизведение
      settings/              # настройки пользователя и языка
    services/
      api/                   # клиент серверного API
      storage/               # интерфейс хранилища
      i18n/                  # локализация интерфейса и языковые настройки
    styles/                  # стили
  server/
    src/
      routes/                # API endpoints
      providers/             # адаптеры ИИ-провайдеров
      services/              # память, диалоги, списки, напоминания
      security/              # валидация и защита запросов
  docs/
    ARCHITECTURE.md
```

Это целевая схема, а не утверждение, что все перечисленные модули уже реализованы.

## Основные модули

- **Chat:** отправка сообщений, потоковые ответы при поддержке провайдера, история диалогов и определение языка.
- **AI provider adapter:** единый интерфейс для подключения и смены языковой модели.
- **Memory:** отдельное хранилище подтверждённых пользовательских фактов и предпочтений; управление и удаление должны быть доступны пользователю.
- **Lists:** независимые списки «Хочу сделать», «Хочу посмотреть», «Мои хотелки».
- **Reminders:** разовые и повторяющиеся напоминания с датой, временем и статусом.
- **Voice:** независимые адаптеры распознавания речи и синтеза речи с поддержкой русского и украинского языков.
- **i18n:** переводы интерфейса, локализованные даты и форматы, отдельная настройка языка интерфейса.
- **Settings:** настройки модели, языка интерфейса, языка общения, голоса, приватности и поведения ассистента.\n- **Focus control:** управление системными режимами Фокусирования через пользовательские Apple Shortcuts в PWA; при переходе на нативное приложение исследовать App Intents и Controls.

## Безопасность

- Секретные ключи хранятся только в переменных окружения серверной среды.
- Нельзя помещать API-ключи в HTML, JavaScript клиентской части, Git или логи.
- Сервер валидирует входные данные и ограничивает частоту запросов.
- Для персональных данных предусматриваются аутентификация, минимизация хранения и удаление данных.
- Service worker не должен кэшировать приватные API-ответы или данные авторизованных пользователей.

## План реализации

1. Зафиксировать архитектуру и отделить клиентскую часть от будущего серверного API.
2. Выбрать и настроить серверную платформу и безопасное хранение секретов.
3. Реализовать текстовый чат, историю и двуязычное поведение.
4. Реализовать хранилище и пользовательские списки.
5. Реализовать напоминания.
6. Исследовать старый проект и установить точную технологию голоса `ru m5`; затем подключать распознавание и синтез речи для русского и украинского.
7. Добавить локализацию интерфейса, настройки языков и тесты обоих языков.
8. Добавить обработку ошибок, резервное копирование и PWA-совместимость.

## Текущий статус

В ветке `foundation/architecture` реализованы клиентская навигация, локальные списки, локальное хранилище и клиент будущего API. Списки работают в браузере одного устройства. Серверный API, аутентификация, синхронизация, подключение ИИ, полноценная локализация и голосовой модуль ещё не реализованы. Напоминания сохраняют расписание, но пока не создают системные уведомления. Раздел файлов остаётся заглушкой. В настройках доступны экспорт и импорт локальной резервной копии.


## Фокусирование на устройствах Apple

JARVIS должен понимать команды на русском и украинском для включения «Не беспокоить», «Сон», «Учёба», «Личное» и пользовательских режимов, выключения режима, установки длительности и выбора iPhone/iPad. В текущей PWA добавляется мост к Apple Shortcuts по URL-схеме. Пользователь должен один раз создать соответствующие Shortcuts на устройстве; PWA не имеет прямого API для переключения системного Focus. Запуск Shortcut не доказывает, что системный режим изменился. Для полностью интегрированного нативного опыта потребуется отдельная проверка возможностей App Intents и системных API.


## Автономная работа без интернета

Офлайн-режим является обязательным требованием:

- После первой успешной загрузки приложение должно открывать закэшированную оболочку без Wi-Fi и мобильной сети.
- Списки, настройки, черновики и доступная локальная история должны читаться и изменяться без сети.
- Локальные операции выполняются на устройстве; сетевые функции явно показывают отсутствие соединения и не блокируют локальные функции.
- Для автономного диалога нужен отдельный локальный inference-адаптер с моделью на устройстве. Облачная модель не считается офлайн-решением. Модель загружается заранее; размер, скорость, расход батареи и совместимость с iPhone 13 Pro/iPad A16 необходимо измерить.
- Локальная модель должна иметь ограниченный контекст и безопасный режим; качество облачной модели нельзя обещать без сравнительных тестов.
- Голосовой режим офлайн требует локального распознавания и синтеза речи. Для русского голоса сначала восстановить исходный ru m5; не заменять его без согласования.
- Синхронизация выполняется при восстановлении сети, с обработкой конфликтов и без потери локальных изменений.
- Service worker не должен кэшировать приватные API-ответы или секреты.

## Контроль заряда устройств и вечерняя проверка

Требуется отдельный модуль Device Status / Evening Readiness:

- Перед выбранным временем сна ассистент формирует сводку о заряде iPhone, iPad, AirPods и Apple Watch, если данные доступны.
- Предупреждать при низком заряде или индивидуальном пороге; пороги и время проверки настраиваются.
- Формулировать рекомендации практично: какие устройства стоит зарядить до утра. Не повторять предупреждения без изменения состояния.
- Учитывать актуальность показания, источник и доступность данных. Если уровень заряда неизвестен или устарел, прямо обозначать это, а не придумывать процент.
- Пользователь может отключить отдельные устройства, изменить пороги, время и тихие часы.

Ограничения платформы:
- PWA не имеет универсального API для чтения заряда iPhone, iPad, Apple Watch и AirPods.
- Нативное iOS-приложение может читать собственный заряд iPhone/iPad через публичный API UIKit.
- Данные Apple Watch могут потребовать companion watchOS-приложения и передачи показаний через WatchConnectivity; возможность и точность нужно проверить на реальном устройстве.
- Для AirPods нельзя обещать стабильный публичный API для чтения заряда сторонним приложением. Исследовать только документированные API и фактически доступные аксессуарные данные; не использовать private API.
- Если источник недоступен, пользователь может вручную задать заряд или отключить устройство из вечерней проверки.
- Вечернее напоминание должно работать локально по расписанию, когда ОС разрешает доставку уведомлений. Нельзя обещать выполнение фонового кода в точную минуту: iOS управляет временем фоновых задач и уведомлений.
