# Оценка бесплатной основной ИИ-модели JARVIS 2

Дата проверки: 2026-11-22

Статус: предварительный технический выбор. Живое сравнение качества на API ещё не выполнялось.

## Краткий вывод

Первый кандидат для технического прототипа: `openai/gpt-oss-120b` через Groq.

Резервный кандидат: бесплатный вариант NVIDIA Nemotron 3 Ultra через OpenRouter.

Не объявлять ни одну модель окончательно выбранной до одинаковых тестов на русском, украинском, контекстной памяти и вызове функций. Название модели, доступность и бесплатные лимиты у провайдеров могут меняться.

## Почему GPT-OSS-120B / Groq — первый кандидат

По официальной документации Groq на дату проверки:

- модель доступна под ID `openai/gpt-oss-120b`;
- поддерживает локальный вызов функций и встроенные инструменты;
- для GPT-OSS доступны встроенные browser search и code execution;
- заявлено окно контекста 131 072 токена;
- бесплатный Developer/free tier указывает лимиты для этой модели: 30 запросов в минуту, 1 000 запросов в день, 8 000 токенов в минуту и 200 000 токенов в день. Фактические лимиты конкретной организации нужно проверять в её панели.

Официальные источники:
- https://console.groq.com/docs/models
- https://console.groq.com/docs/rate-limits
- https://console.groq.com/docs/tool-use/overview
- https://console.groq.com/docs/tool-use/built-in-tools

Преимущества для JARVIS 2:
- есть documented function/tool calling для связи модели с нашими функциями;
- можно использовать одну модель для диалога и вызова встроенных инструментов;
- быстрый inference подходит для диалога с несколькими итерациями вызова функций;
- бесплатный лимит на бумаге выше, чем у бесплатных моделей OpenRouter.

Ограничения и риски:
- 8 000 токенов в минуту могут стать узким местом при длинной истории;
- лимиты бесплатного доступа не являются гарантией бесперебойной работы;
- качество русского и украинского именно для наших сценариев ещё не измерено;
- нельзя отправлять личную историю или файлы, пока не проверены условия обработки данных и не реализованы приватность и минимизация контекста.

## Резерв: NVIDIA Nemotron 3 Ultra / OpenRouter

Официальный каталог бесплатных моделей OpenRouter на дату проверки показывает Nemotron 3 Ultra среди наиболее используемых бесплатных вариантов.

У бесплатных моделей OpenRouter с суффиксом `:free` указаны ограничения 20 запросов в минуту и 50 запросов в день. OpenRouter также предупреждает о лимитах конкретного провайдера и доступности.

Официальные источники:
- https://openrouter.ai/collections/free-models
- https://openrouter.ai/pricing

Почему оставить резервом:
- современная модель с упором на reasoning и orchestration;
- полезна как независимая вторая модель для сравнительных тестов;
- бесплатный маршрут можно проверить без оплаты, но дневной лимит существенно ниже Groq.

## Почему не фиксируем Qwen как бесплатный основной вариант

На странице моделей Groq `qwen/qwen3.8-27b` присутствует в каталоге и поддерживает tool calling, включая параллельный вызов функций. Однако текущая страница моделей показывает для него платную тарификацию, поэтому нельзя называть его бесплатным API-вариантом на этой платформе. Его можно повторно рассмотреть, если появится подтверждённый бесплатный маршрут.

Источник: https://console.groq.com/docs/models и https://console.groq.com/docs/tool-use/overview

## План честного сравнения

Все кандидаты получают одинаковые запросы, одинаковый системный prompt, одинаковую историю и одинаковые определения функций. Оценивать по шкале 0–5:

1. Естественность и точность русского.
2. Естественность и точность украинского.
3. Сохранение языка пользователя при переключении между языками.
4. Понимание длинных и разговорных команд.
5. Следование контексту предыдущих реплик.
6. Правильность выбора функции и аргументов.
7. Отказ от выдумывания результатов действий.
8. Скорость ответа и устойчивость к временным ошибкам.
9. Работа в пределах реальных бесплатных лимитов.
10. Приватность и условия использования данных.

### Тестовые сценарии

- Русский: «Добавь в “Хочу сделать” подготовить презентацию к четвергу».
- Украинский: «Нагадай мені завтра о 18:30 перевірити домашнє завдання».
- Смешанная речь: пользователь начинает по-русски, затем уточняет задачу по-украински.
- Контекст: сначала задать задачу, затем попросить изменить её срок без повторения названия.
- Неоднозначность: «Напомни мне об этом позже» — модель должна запросить дату или время, а не выдумывать.
- Tool calling: создать, изменить, завершить и удалить тестовую запись через строго описанные функции.
- Защита от галлюцинаций: попросить перечислить задачи, когда функция вернула пустой список; модель не должна придумывать записи.
- Длинный контекст: проверить, сохраняет ли модель детали из нескольких предыдущих реплик.
- Ошибка инструмента: функция возвращает ошибку; модель должна честно сообщить, что действие не выполнено.
- Секреты: в тестовый prompt поместить фиктивный маркер; модель не должна просить или повторять реальные ключи.

Результат записывать в таблицу с оценкой, задержкой, ошибками tool calling и числом токенов. Победитель выбирается по качеству, надёжности, приватности и лимитам, а не по популярности.

## Архитектурное решение

- Не привязывать клиент к Groq, OpenRouter или конкретной модели.
- Все обращения к модели идут только через серверный адаптер.
- Имя провайдера и model ID задаются серверной конфигурацией.
- Секреты хранятся только в защищённом серверном хранилище, не в Git, HTML или браузере.
- Предусмотреть резервный провайдер, но переключать на него только при корректной обработке ошибок и подтверждённой совместимости функций.
- Память, история, списки, напоминания и голос остаются собственными модулями JARVIS 2, не принадлежат модели.
- Модель не должна сама объявлять, что задача создана или напоминание установлено: это подтверждается только результатом функции.
